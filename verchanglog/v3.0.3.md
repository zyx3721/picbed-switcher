## 📋 版本概述

v3.0.3 聚焦二进制部署路径与邮箱验证体验修复。`scripts/` 运维脚本与 README 双文档的 Release 二进制部署章节路径对齐实际平铺部署布局（安装目录下直接放置 `picbed-switcher` 二进制、`dist/` 前端静态目录、`app.pid` 与 `app.log`）；SMTP 新增明文认证支持，`SMTP_SECURITY=none` 时直接使用明文 PLAIN 认证，适配仅支持明文认证的内网 SMTP 服务器；邮箱验证成功后自动清空该用户在 `email_verification_tokens` 表中的全部记录。

---

## ✨ 新增特性

- SMTP 支持明文认证：`SMTP_SECURITY=none` 时改用自定义 PLAIN 认证实现，绕过 Go 标准库 `smtp.PlainAuth` 对未加密连接的限制，填写的 `SMTP_USERNAME`/`SMTP_PASSWORD` 可在明文连接上正常完成认证；`ssl`、`starttls`、`auto` 模式行为保持不变。
- 邮箱验证成功后清空验证记录：验证通过的事务内在标记邮箱已验证的同时，按用户物理删除 `email_verification_tokens` 表中该用户的全部 token 记录（含未使用的历史记录），表内不再残留数据。

---

## 🐛 Bug 修复

- 修复 `scripts/update-picbed-switcher.sh` 按旧 `backend/`、`frontend/` 子目录布局写路径的问题：安装目标对齐为安装根目录下的 `picbed-switcher`、`dist/`、`app.pid`、`app.log`，备份文件调整为根目录下的 `picbed-switcher.bak` 与 `dist.bak`，避免更新时产物落到错误目录。
- 修复 `SMTP_SECURITY=none` 且配置账号密码时发信必然失败的问题：标准库在非 TLS 连接上拒绝发送凭据（`unencrypted connection`），现按安全模式分流认证实现。
- 修正 README 双文档 Release 二进制部署章节的路径描述：后端包直接解压至安装根目录、前端包解压至 `dist/`，systemd 的 `WorkingDirectory`/`ExecStart` 与 Nginx 静态根目录同步修正。

## 🔄 升级说明

从 v3.0.2 升级到 v3.0.3 无需执行数据库迁移。

**二进制部署升级**：

- 本次更新脚本本身修正了安装路径，升级到本版本前请勿使用 v3.0.2 的 `scripts/update-picbed-switcher.sh` 在线更新（旧脚本会把产物装入 `backend/` 子目录）；请手动下载产物替换安装根目录下的 `picbed-switcher` 二进制后重启，或先以新版脚本覆盖服务器上的旧脚本。
- 升级后可执行 `./picbed-switcher -v` 确认版本为 `v3.0.3`。

**SMTP 明文认证**：

- 仅支持明文认证的内网 SMTP 服务器保持 `SMTP_SECURITY=none` 即可，无需新增环境变量；公网 SMTP 建议优先使用 `auto`（STARTTLS）或 `ssl`。

**Docker 部署升级**：

- 拉取新镜像后按原命令重新创建容器即可。
